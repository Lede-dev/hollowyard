# Hollowyard 공지·이벤트 게시 워크플로

새 공지 또는 이벤트를 `/news` 목록과 상세 페이지에 게시할 때 사용하는 절차입니다.

## 1. 게시 전 준비

- 영문 소문자와 하이픈으로 구성된 고유한 `slug`
- 한국어·영어 제목과 한 줄 요약
- 게시일
- 공지 또는 이벤트 분류
- 게시 상태
- 본문 섹션과 관련 링크
- 이벤트라면 시작일과 종료일

## 2. 게시글 데이터 등록

1. `docs/templates/news-entry.template.md`의 객체를 복제합니다.
2. `lib/posts.ts`의 `newsPosts` 배열 마지막에 추가합니다.
3. 최신 게시글이 위에 표시되도록 `publishedAt`을 `YYYY-MM-DD` 형식으로 입력합니다.
4. `type`은 `notice` 또는 `event`를 사용합니다.
5. `status`는 `published`, `ongoing`, `ended` 중 하나를 사용합니다.
6. 목록에서 강조할 게시글은 `featured: true`로 설정합니다.
7. 관련 페이지나 외부 문서는 `links`에 추가합니다. 링크가 없으면 빈 배열을 사용합니다.

## 3. 이벤트 게시 규칙

- 이벤트에는 `eventPeriod.start`와 `eventPeriod.end`를 모두 입력합니다.
- 시작 전이나 진행 중에는 `status: "ongoing"`을 사용합니다.
- 종료 후에는 `status: "ended"`로 변경합니다.
- 이벤트 기간과 게시 상태가 서로 모순되지 않는지 확인합니다.

## 4. 검증

```bash
npm test
```

확인 항목:

- `/news` 목록에 새 글이 표시되는가
- 공지·이벤트 필터와 검색에 포함되는가
- `/news/{slug}` 상세 페이지가 생성되는가
- 한국어와 영어 제목·본문이 모두 표시되는가
- 이벤트 기간과 상태가 정확한가
- 내부 및 외부 관련 링크가 올바르게 열리는가
- 모바일에서 카드와 본문이 한 열로 정렬되는가

## 5. 배포

검증이 끝난 변경을 `main`에 반영하면 GitHub Actions가 Cloudflare 배포를 수행합니다. 배포 후 공개 목록과 상세 URL을 확인합니다.
